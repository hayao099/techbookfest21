# あとがき

技術加速研究所の初書籍､いかがでしたでしょうか｡今回はLLMをテーマに様々な方向性のセクションがあり､自画自賛になってしまいますが面白い本になったかなと思います｡  
自分のセクションでは今後もより利用や構築が増えるであろうAIエージェントの権限認可についての知識を改めて整理することができたので､ぜひ皆様の業務や個人開発でも参考になれば幸いです｡(みどり)

本書のプロジェクトを通して痛感したのは、「LLMは単なるコード生成器ではなく、ソフトウェア・知識ベース・ハードウェアを横断する総合エンジニアリングの相棒である」 ということでした。

APIのエラーや先頭ゼロ消失の罠に頭を抱えながらも、Webの海を泳ぎ、LLMに助けられながらコードを書き、ジャンクの光学ドライブを物理的にハックしていくプロセスは、想像以上にエキサイティングな体験でした。「文系だろうが非エンジニアだろうが、自分の手で便利な仕組みを形にできる」——それこそが、個人開発や同人誌執筆の最大の醍醐味だと感じています。（よしお）

最近よく使っているMCPやSkillを題材に、AIと開発を進めるうえで、普段の作業を少し楽にする方法を試すことができました。
AIエージェントに作業を任せることが増え、自分で手を動かす機会は減ってきました。今回の検証を通じて、AIに伝えた指摘とその理由を残しておくことは、自分が開発で何を大切にしているのかを振り返る手がかりにもなると感じました。（kushizam）

こんなマニアックな検証に最後まで付き合って読んでくださったみなさん、ありがとうございます。
チューニングによるスループットの向上幅はわずか数％にとどまりましたが、それはメモリ帯域の物理限界まで性能を引き出しきった証拠でもあります。
10年前のCPUであっても、適切な最適化を行えば35BクラスのMoEモデルを毎秒約19トークンという実用的な速度で動作させることが可能です。
Claude CodeやCodexなどのクラウドサービスでトークン上限に達してしまい、作業がストップしたときの「代替・避難先」としても、それなりに実用的です。
ぜひ格安マシンを限界まで使い倒してみてください。 (880)
